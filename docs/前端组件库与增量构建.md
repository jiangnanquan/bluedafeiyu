# 前端组件库与增量构建

公开前端使用一套页面外壳、一套设计变量和一套组件库。页面只组合组件，组件负责结构、样式和交互状态。站点由 Astro 生成静态文件，业务数据继续来自正式清单。

## 源码同步

每次本地更新前，读取线上 `/build-info.json`，核对代码提交、内容提交和远端 `main`。先保存未提交改动，再以快进方式同步本地主目录与图片仓。功能开发使用最新 `origin/main` 的独立工作树。不要把其他任务的改动混入发布。

发布完成后，再同步本地主目录，核对本地、远端和线上三个位置的提交。保存代码成功不代表线上已经更新；线上状态以发布记录和实际页面验证为准。

## 组件入口

| 能力 | 维护位置 |
| --- | --- |
| 唯一 HTML 文档、SEO、语言和脚本入口 | `src/layouts/Archive.astro` |
| 侧栏、顶栏、手机抽屉和内容容器 | `src/components/library/SiteShell.astro` |
| 全站外壳、主题和通用控件样式 | `src/components/library/styles.css` |
| 明暗配色、外壳和基础角色卡 | `src/components/library/DesignSystem.css` |
| 字号、间距、控件、列表、详情和文档组件 | `src/components/library/ArchiveContent.css` |
| 预览、分享、ZIP 下载和反馈状态 | `src/components/library/Overlays.css` |
| 统一页面标题 | `src/components/archive/PageHeading.mjs` 和 `PageHeading.astro` |
| 静态与动态作品卡片 | `public/components/work-card.js` |
| 瀑布流排列与动态尺寸 | `src/components/layout/Masonry.mjs` 和 `public/components/runtime.js` |
| 首页组合 | `src/components/archive/PageComposition.mjs` |
| 角色内容骨架与品牌变量 | `CharacterPage.css` 和 `CharacterBrandTokens.css` |
| 视频、作者、项目、连载和活动 | `src/components/archive/` 中对应的业务组件 |
| 关于、投稿和日志 | `src/components/pages/` |

页面组件统一使用 `Archive` 与 `SiteShell`。业务组件在自己的入口导入样式。首页、作品详情、视频和作者档案各有样式入口，分页复用对应的组件。共享样式入口只放外壳、主题、通用控件和全站弹层需要的样式。

业务路由位于 `src/pages/`，只能读取数据并调用组件。路由不得添加任意类名、CSS 导入、样式参数或内联样式。缺少能力时，先扩展组件参数或增加职责明确的组件。

原来的 `public/styles.css`、`tokens.css`、`v2.css`、`public/page-styles/`、多轮 `original-*`、`demo-*`、`journal-*` 样式，以及 Notebook 和旧页面外壳已经退出公开前端。不得重新引入这些入口，也不得通过新增覆盖文件恢复旧效果。

## 设计与状态规则

颜色使用 `--paper`、`--surface`、`--card`、`--ink`、`--muted`、`--line`、`--blue` 等语义变量。明暗主题成对维护。字号、间距、圆角、动画时长和层级使用公共变量；组件专有尺寸保留在所属组件中。

按钮统一提供默认、悬浮、按下、键盘焦点、禁用和处理中状态。手机端操作不能依赖悬浮。尊重减少动效偏好，悬浮和按下不能推动周边布局。

同一作品在首页、图库、搜索、收藏和动态加载中使用同一个卡片渲染器。真实详情地址、稳定 ID、原图、署名和许可由正式记录提供。普通点击图片或标题打开预览；预览里的“查看详情”进入详情页。作者、收藏、分享和下载维持独立操作。

合集卡支持普通行卡和 `compact` 变体。目录使用行卡，角色页的相关合集使用紧凑变体；不要在页面临时改按钮边距适配卡片宽度。

静态样式写在所属组件的 CSS 中。动态定位、瀑布流尺寸和滚动锁定只通过 `SiteComponents` 的具名操作处理。不得增加接受任意 CSS 属性的通用写入接口。

## 内容与语言

普通图库排除连载封面及正文，连载保留原稿页码和独立入口。主题成员、顺序与封面由人工清单决定。零作品角色不自动加入公开目录。数量从实际展示集合计算。

`a` 表示投稿署名，`sa` 表示来源作者。缺失来源作者时显示“原作者未标注”，不得把投稿者推断为原作者。作品的 ID、slug、版权、原图路径和评论串保持稳定。

角色页共用 `CharacterPage.css`。品牌文件只提供颜色、字体、纹理和装饰变量，不写布局规则。品牌作用域限于内容区，侧栏和顶栏使用站点公共配色。透明角色图的绑定继续由 `data/character-portraits.json` 管理。

界面支持简中、繁中、英语和日语。语言菜单跳到当前页的对应语言地址，保留查询参数和锚点。新文案在组件工厂初始化时登记翻译，不能等延迟模板渲染时才登记。英语和日语的作品正文读取真实译文；繁体通过既有 OpenCC 流程生成。作者姓名保持原名。

投稿和视频登记复用正式 API 与 Turnstile。成功状态必须来自服务端响应。合集下载继续生成真实 ZIP，保留失败重试、取消和体积限制。浏览器收藏继续读取已有存储键，避免更新后丢失已有收藏。

## 检查与预览

```powershell
npm --prefix frontend run check:components
npm --prefix frontend run test:unified
node tools/build_site.mjs --content-dir <内容仓目录> --out .build/site --full
node tools/preview_site.mjs --dir .build/site --port 8801
```

开发服务的 `/dev/components` 展示按钮、作品卡、角色卡、合集、表单和空态。开发展示页不进入正式发布目录。静态预览使用 `tools/preview_site.mjs`，该工具仅挂载允许公开的首批派生图，不暴露编辑清单。

验收覆盖所有页面族、公开角色、四种语言、明暗主题，以及桌面和手机宽度。检查筛选、搜索、加载更多、预览前后张、焦点恢复、收藏、下载、分享和表单状态。自动路由检查覆盖全部产物，人工检查覆盖每类模板。测试记录与截图放在项目 `.build/qa/`。

组件检查器同时校验路由边界、样式归属、已退出入口和唯一外壳。不得为了通过检查而登记旧 CSS，或移除仍然有效的业务断言。

## 增量构建

`tools/build_site.mjs` 默认使用上一次成功的产物作为基线。Astro 根据模板和样式的依赖关系复用页面，构建器再比较每条路由的数据。修改业务组件时，受影响的页面包括它的所有入口和分页。修改全站布局时，所有使用该布局的页面都要重建。

原始 HTML 和该页使用的翻译输入都相同时，直接复用四种语言的产物。英日文审计随产物保存，复用前仍比较审计规则和相关输入。缺少基线、校验失败或工具链变化时运行全量构建。普通更新保留 `.build/astro-cache/`。

```powershell
node tools/build_site.mjs --content-dir <内容仓目录> --out .build/site
node tools/build_site.mjs --content-dir <内容仓目录> --out .build/site --plan-only
node tools/build_site.mjs --content-dir <内容仓目录> --out .build/next --previous .build/site
```

`--full` 控制完整构建，`--force-clean` 只控制指定旧输出目录的清理。修改构建或组件边界后，执行 `test:incremental:integration`，比较同一输入的增量和完整产物。

构建先检查组件、暂存清单、同步图片和生成快照。随后处理 HTML、分享图、多语言、Markdown、开放 API 和站点地图。`build-info.json` 记录分段耗时、实际渲染数和语言版复用数。`--plan-only` 报告路由数据变化。实际模板重建范围以构建后的 `rendered` 记录为准。

作品详情依赖自身、所属专题和实际使用的推荐作品。聚合页以页面内容和元数据判断是否变化。未变化的正文保留 sitemap 日期。缺图超过 1% 时中止，成功后才替换产物目录。

## 发布

代码与图片通过各自 Git 仓库同步到服务器。服务器运行 `ops/deploy-server.sh` 的副本，在独立 staging 目录构建并原子切换 `current`。健康检查失败恢复上一版 release。禁止上传本地整包覆盖正式目录。

后台预检和部署共用构建产物。服务器拉取源码和图片后，校验预检输入及产物摘要。校验通过时直接使用候选包，校验失败时按服务器输入构建。预压缩按原文件和 gzip 摘要复用；新文件和内容变化的文件重新压缩。

`build-state/` 和构建影响清单只保存在服务器。公开的 `/build-info.json` 记录版本、计数和耗时。发布仍需通过产物缺图门禁与健康检查。
