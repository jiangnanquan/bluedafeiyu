## 最终发布门禁

每个最终候选执行以下步骤，检查日志作为实际验收记录。

1. 推送源码和内容分支，复核 CI 与明确的提交版本，再快进正式分支。
2. 使用本轮源码完整构建，执行多语言审计、完整回归和组件归属检查。共享组件及样式入口变化是本轮完整重建的原因。
3. 服务器从 Git 拉取相同版本，构建、预压缩，检查真实发布产物的缺图情况和 nginx 配置。
4. 最终验证通过后原子切换 `current`，执行健康检查；失败时按发布脚本回退。候选包构建完成不等于已上线。
5. 回读正式域名的版本、主要页面、社群入口与二维码，再同步本地主目录、远端和内容仓。保留此前未提交修改的备份。

本地构建预览使用 8801；开发服务与原稿仅用于核对，不能作为服务器发布产物。本机检查输出保存在忽略的 `.build/qa/`，后续核查必须结合当次日志和线上版本。
